Build a complete working prototype for the DRDO Smart India Hackathon problem:

**SIH26054 — AI-Enabled Real-Time Digital Twin System for Aero Piston Engines in MALE UAVs**

# 1. IMPORTANT ENGINEERING RULES

Follow these rules throughout the implementation:

* Build a real runnable system, not pseudocode.
* Do not leave major components as TODO placeholders.
* Use clean modular architecture.
* Every major prediction must have an explainable evidence trail.
* Keep physics simulation, sensor simulation, AI inference, mission simulation and UI logically separated.
* Do not directly modify sensor values to simulate mechanical faults.

Physical fault
→ engine subsystem state
→ engine observable state
→ sensor measurements
→ digital twin residual
→ anomaly detection
→ diagnosis
→ degradation
→ mission risk.

Sensor faults must be simulated separately:

# 9. DIGITAL TWIN

The digital twin must maintain two parallel states:

```text
ACTUAL / OBSERVED ENGINE
        ↓
      sensors

HEALTHY EXPECTED ENGINE
        ↓
physics model
```

Calculate:

```text
residual = observed - expected
```

Normalize residuals using channel uncertainty.

Implement:

```text
r_i = (observed_i - expected_i) / sigma_i
```

Track residual trends over time.

Do not trigger a fault solely from one abnormal sensor sample.

# 10. SENSOR VS ENGINE FAULT SEPARATION

This is a critical feature.

The system should determine whether abnormal telemetry is caused by:

```text
1. Sensor fault
2. Physical engine fault
3. Model mismatch
4. Unknown anomaly
```

Example:

If EGT3 suddenly increases but:

* EGT1/2/4 remain normal
* CHT3 remains normal
* vibration remains normal
* fuel flow remains normal

the system should increase the probability of:

```text
EGT3 SENSOR FAULT
```

rather than:

```text
CYLINDER FAILURE
```

But if:

```text
EGT3 abnormal
CHT3 abnormal
fuel flow abnormal
vibration abnormal
```

the physical fault probability should increase.

Create a dedicated sensor integrity score.
